# 安全构建格式版本

保留旧 `md` 分支维护技能的用途，使用仓库的确定性构建器，不再逐文件全局替换，也不隐式操作用户安装。

## 输入与范围

- 从当前打开的仓库定位 `scripts/build_format.py`；不要假定用户名、Home 路径或安装位置。
- 若当前只是单独安装的技能，没有仓库构建器，明确报告需要项目源码，不能生成猜测路径或回退到旧全局副本。
- 默认构建 Markdown 副本；用户明确要求 Org 时选择 `--format org`。
- 输出必须是用户指定的新目录，或仓库 `.cache/` 下唯一的新目录。已有输出目录会被拒绝，不能删除它来绕过保护。

## 执行

在仓库根目录，以包含空格也正确的路径运行：

```sh
python3 scripts/build_format.py --format md --output "<新的输出目录>"
python3 scripts/check.py --format md
```

第一条生成完整、可检查的格式副本，包括技能、依赖声明、检查入口与 CI。第二条对当前源码构建的 Markdown 副本运行验证；不是只搜索关键词。

转换器必须保留 URL、原始输入示例、普通代码块和二进制资源。只有明确的输出模板与格式契约可以转换；YAML 元数据必须有完整边界和正确类型。无法转换或存在目标冲突时停止，不生成混合格式的“成功”副本。

## 安全边界

- 默认只读取源目录、写入新输出目录，不修改源文件。
- 不执行 Git 提交或推送，不覆盖全局或项目安装的技能，不运行删除式同步。
- 用户另行明确要求提交、安装或发布时，再按对应流程核对精确目标；此技能的调用不是那些操作的授权。
- 不直接修补生成的 `md` 分支；将修正保留在源模板、转换器或回归测试，再重建。

## 完成报告

报告源目录、目标格式、输出目录、文件清单/哈希校验结果和实际运行的验证命令。测试失败必须明确列出；未运行测试不能称为验证通过。说明是否执行了额外的提交、安装或发布；默认均为未执行。
